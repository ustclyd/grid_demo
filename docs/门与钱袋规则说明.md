# 门与钱袋规则说明

本文档只记录当前代码里已经落地的“`portal / exit_portal` 与钱袋交互”规则，用于后续继续开发时快速对照。

对应代码入口：
- [TurnResolver](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd)
- [BagState](d:/GameDev/grid_demo/scripts/model/bag_state.gd)
- [Main.gd](d:/GameDev/grid_demo/scripts/Main.gd)

## 1. 当前目标

当前已经实现：
- 钱袋可进入普通 `portal`
- 钱袋可进入 `exit_portal`
- 钱袋可与人物在同一门格一起预约
- 钱袋可在撤离时把金币结算给同格撤离人物
- `portal` 过热和 `exit_portal` 刷新都已接通

当前还未实现：
- 专门的门上钱袋动画表现
- 钱袋的独立 UI 历史记录
- 更复杂的随机刷新策略

## 2. 钱袋数据结构

当前 `BagState` 除了位置和金币外，还包含门相关跨回合状态：

- `has_queued_teleport`
- `queued_teleport_to`
- `queued_exit`

代码位置：
- [bag_state.gd:10](d:/GameDev/grid_demo/scripts/model/bag_state.gd#L10) 到 [bag_state.gd:12](d:/GameDev/grid_demo/scripts/model/bag_state.gd#L12)

这意味着钱袋和人物一样，支持：
- 本回合结束时预约
- 下一回合开始时执行

## 3. 普通传送门与钱袋

### 3.1 回合结束时预约

若本回合结算结束后，某个钱袋位于可用且未过热的 `portal` 入口格：
- 该钱袋记录 `has_queued_teleport = true`
- 记录 `queued_teleport_to = 另一端入口`
- 该预约不会在本回合立刻执行

代码位置：
- [turn_resolver.gd:321](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L321) 到 [turn_resolver.gd:355](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L355)

### 3.2 下一回合开始时传送

若某个钱袋在回合开始时已经 `has_queued_teleport = true`：
- 钱袋从当前门入口传送到另一端入口
- 清空预约状态
- 记录到 `teleport_records`
- 该门对进入 3 回合过热冷却

代码位置：
- [turn_resolver.gd:240](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L240) 到 [turn_resolver.gd:279](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L279)

### 3.3 多个对象同时进入同一门格

当前实现允许以下对象同时预约普通门：
- 一个或多个单位
- 一个或多个钱袋

它们会：
- 在同一回合结束时分别记录预约
- 在下一回合开始时一起执行传送
- 只要该门对本回合实际被使用过一次，就统一进入过热

### 3.4 过热结束后的再次预约

当前实现符合这条时序：
1. 回合开始时先减少冷却
2. 冷却结束后，该门重新可用
3. 若本回合结束时入口格上仍有钱袋或单位
4. 它们会再次预约下一回合传送

## 4. 撤离门与钱袋

### 4.1 回合结束时预约

若本回合结算结束后，某个钱袋位于 `exit_portal` 上：
- 记录 `queued_exit = true`
- 本回合不立刻离场

代码位置：
- [turn_resolver.gd:358](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L358) 到 [turn_resolver.gd:381](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L381)

### 4.2 下一回合开始时执行撤离

若某个钱袋在回合开始时已经 `queued_exit = true`：
- 若同格也有 `queued_exit` 的人物
  - 先把钱袋金币结算给该人物
  - 再将钱袋移除
  - 再让人物撤离
- 若同格没有人物
  - 钱袋直接随撤离门离场并消失

代码位置：
- [turn_resolver.gd:101](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L101) 到 [turn_resolver.gd:164](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L164)

### 4.3 撤离门刷新

只要本回合开始阶段有任何对象通过 `exit_portal` 离场：
- 旧撤离门消失
- 新撤离门刷新到新的合法格
- 记录 `exit_refresh_records`

代码位置：
- [turn_resolver.gd:167](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L167) 到 [turn_resolver.gd:189](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L189)

当前刷新合法格规则：
- 不可与旧门同格
- 不可有存活且未胜利的单位
- 不可是普通 `portal`
- 不可是已有 `exit_portal`
- 不可是风暴格

## 5. 当前实现假设

### 5.1 人物与钱袋同时撤离时，金币结算给谁

当前实现使用：
- 同格所有 `queued_exit` 人物中，`id` 最小者作为金币接收者

代码位置：
- [turn_resolver.gd:136](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L136) 到 [turn_resolver.gd:137](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L137)
- [turn_resolver.gd:412](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L412) 到 [turn_resolver.gd:418](d:/GameDev/grid_demo/scripts/rules/turn_resolver.gd#L412)

这只是保护性兜底。按正常回合规则，同格在回合结束后通常只会剩一个可撤离人物。

### 5.2 钱袋不会参与冲突判定

当前实现里：
- 钱袋不会参加 `Conflict1 / Conflict2`
- 钱袋只参与位置、预约、传送、撤离、显示

### 5.3 门上钱袋当前以规则优先

当前已经优先保证：
- 规则正确
- HUD 可见
- 自动化冒烟测试可跑

当前尚未正式处理：
- 门上钱袋的完整动画
- 悬停高亮
- 更细的视觉提示
