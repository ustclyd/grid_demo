# 回合执行表现顺序

本文档用于规定“回合执行阶段”在屏幕上的表现顺序。

本文档不负责定义游戏规则真假，只负责定义：
- 规则结算完成后，画面按什么顺序播放给玩家看
- 每类动作大概持续多久
- 哪些表现是必须的，哪些可以后期再加
- 后续代码层如何分层实现

关联文档：
- `回合结算顺序说明` 负责规则真相
- 本文档负责演出顺序与播放节奏

---

## 一、设计原则

### 1. 规则先算完，再播放
- 每个回合到达结算时点后，先由 `TurnResolver` 一次性算出本回合最终结果
- 不在播放动画的过程中临时改规则结果
- 表现层只读取结算结果，不改写规则状态

### 2. 表现顺序要帮助玩家理解规则
执行阶段的主要目的不是“炫”，而是让玩家看懂：
- 谁想做什么
- 谁先到了哪里
- 谁在第一次冲突中活了
- 谁被钱袋砸回
- 谁在第二次冲突中死了
- 地图最后变成了什么样

### 3. 第一版表现要简单、清楚、可验证
第一版原型不需要复杂特效。
第一版优先实现：
- 位移
- 钱袋投掷
- 钱袋拾取
- 冲突存活/死亡反馈
- 砸回反馈
- 传送/撤离反馈
- 最终棋盘状态停顿

---

## 二、推荐代码分层

建议后续代码按三层实现。

### 1. `TurnResolver`
职责：
- 只计算规则结果
- 输入 `GameState + intents`
- 输出“本回合结算结果”

不负责：
- Tween
- 节点动画
- UI 播放顺序
- 等待时间

### 2. `TurnPresentation` 或 `TurnPlayback`
职责：
- 把 `TurnResolver` 的结算结果，转换为“表现事件序列”
- 例如：
  - `show_intent`
  - `move_unit`
  - `throw_bag`
  - `pick_bag`
  - `conflict1_result`
  - `knockback_unit`
  - `conflict2_result`
  - `drop_bag`
  - `teleport_unit`
  - `exit_unit`

不负责：
- 真正修改规则状态
- 决定谁活谁死

### 3. `Main.gd` 或场景控制器
职责：
- 驱动 `Tween / Timer / AnimationPlayer`
- 按顺序播放 `TurnPresentation` 生成的表现事件
- 播放完成后再进入下一回合输入阶段

---

## 三、执行阶段总时长建议

### 第一版建议
- 执行阶段总时长：`2.0s`

这个长度适合当前原型：
- 足够让玩家看清
- 又不会拖得太慢
- 后面可根据内容增减到 `1.6s ~ 2.5s`

---

## 四、第一版推荐表现时间轴

以下是当前建议的第一版时间轴。

| 时间段 | 阶段名 | 建议时长 | 目标 |
| --- | --- | --- | --- |
| `0.00s - 0.20s` | 指令确认 | `0.20s` | 让玩家看到本回合每个单位准备做什么 |
| `0.20s - 0.65s` | 位移与传送到位 | `0.45s` | 展示单位到达理论目标格 |
| `0.65s - 0.90s` | 资源动作表现 | `0.25s` | 展示 `PICK / THROW` 的钱袋变化 |
| `0.90s - 1.15s` | 冲突判定1反馈 | `0.25s` | 展示第一轮格内胜负 |
| `1.15s - 1.35s` | 砸回表现 | `0.20s` | 展示被钱袋砸回原格 |
| `1.35s - 1.60s` | 冲突判定2反馈 | `0.25s` | 展示被砸回后原格的胜负 |
| `1.60s - 1.85s` | 结算结果表现 | `0.25s` | 展示死亡掉落、强制待机、门状态 |
| `1.85s - 2.00s` | 结果停顿 | `0.15s` | 给玩家看清最终局面 |

## 五、各阶段表现内容

## 5.1 指令确认

### 时间
- `0.00s - 0.20s`

### 画面目标
- 让玩家先看到“这回合每个单位打算做什么”

### 建议表现
- `MOVE`：显示小箭头或目标格高亮
- `STAY`：当前格出现短暂待机标识
- `PICK`：目标钱袋高亮
- `THROW`：显示投掷目标格高亮和抛物线预览线

### 第一版可简化为
- 只高亮目标格
- 不做复杂图标

---

## 5.2 位移与传送到位

### 时间
- `0.20s - 0.65s`

### 画面目标
- 让单位移动到“冲突判定1前的理论落点”

### 包含内容
- 正常移动
- 回合开始阶段的 `portal` 传送到位

### 建议表现
- 普通移动：Tween 平移
- 传送：
  - 入口闪烁
  - 单位淡出
  - 在出口淡入

### 注意
- 这里只播放“先到理论落点”
- 不在这个阶段播放砸回

---

## 5.3 资源动作表现

### 时间
- `0.65s - 0.90s`

### 画面目标
- 让玩家看懂钱袋和金币数发生了什么

### `PICK`
- 目标钱袋飞向单位或直接淡出
- 单位头上短暂显示 `+数字`

### `THROW`
- 钱袋从投掷者飞向目标格
- 投掷者头上短暂显示 `-数字`
- 目标格落下一个新钱袋

### 第一版可简化为
- 钱袋直接从起点移动到终点
- 暂不做抛物线

---

## 5.4 冲突判定1反馈

### 时间
- `0.90s - 1.15s`

### 画面目标
- 让玩家看到“第一轮格内谁活了”

### 建议表现
- 失败单位：
  - 闪红
  - 透明度降低
  - 暂不立刻完全消失，避免和后续砸回混淆
- 存活单位：
  - 轻微放大或高亮一次

### 特别说明
- 如果某格后面还会发生砸回，此处只表达“它先赢了第一轮”
- 还不是最终结局

---

## 5.5 砸回表现

### 时间
- `1.15s - 1.35s`

### 画面目标
- 让玩家明确知道：不是直接死，而是被钱袋砸回原格

### 建议表现
- 被砸回单位出现受击反馈
- 单位快速反向移动回 `prev_pos`
- 原目标格上清除该单位占位

### 可选强化
- 目标格显示短暂冲击圈
- 被砸回路径用线条残影表示

---

## 5.6 冲突判定2反馈

### 时间
- `1.35s - 1.60s`

### 画面目标
- 让玩家看懂被砸回后，原格又进行了一次判定

### 建议表现
- 与“冲突判定1反馈”相同
- 但建议用不同颜色或不同闪烁频率，让玩家知道这是第二轮判定

### 第一版建议
- 用同样动画，但在 UI 或日志区标明“冲突2”

---

## 5.7 结算结果表现

### 时间
- `1.60s - 1.85s`

### 包含内容
- 死亡单位消失
- 死亡掉落钱袋
- 被砸回且存活者出现“下回合强制待机”提示
- `portal`/`exit_portal` 预约状态反馈
- 传送门过热反馈

### 建议表现
- 死亡：淡出或缩小消失
- 掉落钱袋：在死亡格弹出一个钱袋
- 强制待机：单位头上短暂出现锁定/待机标识
- `portal` 预约：门闪烁一次
- `exit_portal` 预约：撤离门闪烁一次
- 过热门：门颜色变暗或显示冷却环

---

## 5.8 结果停顿

### 时间
- `1.85s - 2.00s`

### 目标
- 给玩家一个极短暂停顿，看清最终棋盘局面
- 然后切回输入阶段

---

## 六、第一版表现事件类型建议

建议 `TurnPresentation` 输出统一事件列表，例如：

| 事件类型 | 用途 |
| --- | --- |
| `show_intent` | 显示本回合意图 |
| `move_unit` | 普通移动 |
| `teleport_unit` | 传送到位 |
| `pick_bag` | 捡钱袋表现 |
| `throw_bag` | 扔钱袋表现 |
| `conflict1_win` | 第一轮冲突胜者反馈 |
| `conflict1_lose` | 第一轮冲突败者反馈 |
| `knockback_unit` | 被砸回原格 |
| `conflict2_win` | 第二轮冲突胜者反馈 |
| `conflict2_lose` | 第二轮冲突败者反馈 |
| `drop_bag` | 死亡掉落 |
| `mark_forced_stay` | 标记下回合强制待机 |
| `mark_portal_ready` | 标记下回合传送预约 |
| `mark_exit_ready` | 标记下回合撤离预约 |
| `mark_portal_overheat` | 标记传送门过热 |
| `remove_unit` | 最终从画面移除单位 |

---

## 七、第一版最小实现建议

如果你准备开始写代码，第一版表现层不要一次做满。
建议分 3 步。

### 第一步
只做：
- `move_unit`
- `pick_bag`
- `throw_bag`
- `remove_unit`

目标：
- 先把“会动、会掉、会消失”跑通

### 第二步
再加：
- `conflict1_*`
- `knockback_unit`
- `conflict2_*`
- `drop_bag`

目标：
- 让玩家能看懂两次冲突和砸回机制

### 第三步
最后加：
- `teleport_unit`
- `mark_portal_ready`
- `mark_exit_ready`
- `mark_forced_stay`
- `mark_portal_overheat`

目标：
- 把门系统和状态提示补完整

## 八、Godot 实现建议

### 1. 播放方式
第一版建议优先用：
- `Tween`
- `SceneTreeTimer`
- 简单的节点显隐/颜色变化

暂时不必一开始就重度依赖：
- `AnimationPlayer`
- 粒子特效
- 复杂状态机动画

### 2. 场景层建议
可以考虑后续拆成：
- `Main.gd`：总控制器
- `TurnPlayback.gd`：执行阶段播放控制
- `BoardView.gd`：棋盘显示
- `UnitView.gd`：单位表现
- `BagView.gd`：钱袋表现

### 3. 执行流程建议
建议是：
1. `TurnResolver` 产出 `TurnResult`
2. `TurnPresentation` 把 `TurnResult` 转成 `PlaybackEvent[]`
3. `Main.gd` 调用 `await TurnPlayback.play(events)`
4. 播放完成后进入下一回合输入
